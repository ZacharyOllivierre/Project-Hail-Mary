# Projectile Service

[Back to the gameplay API guide](README.md)

## What It Does

`ProjectileService` accepts firing intent from gameplay. It validates the
request and passes it to `ProjectileManager`. The manager schedules each shot,
creates the projectile when its delay expires, adds it to the bound scene, and
registers its physics and entity collision.

## When Gameplay Uses It

Use it after a weapon, enemy, or ability has decided what to fire. The caller
provides the source object, shot descriptions, and collision profile in a
`ProjectileFireRequest`.

## How to Access It

```cpp
#include "../combat/projectile_service.h"

PROJECTILE_SERVICE->request_fire(std::move(request));
```

`PROJECTILE_SERVICE` expands to `ProjectileService::instance()`.

## Main APIs and Data Types

```cpp
void request_fire(ProjectileFireRequest request);
```

`ProjectileFireRequest` contains:

- `source`: a non-owning pointer to the object firing the shots.
- `shots`: a list of `ShotDescriptor` values generated by the weapon or
  ability.
- `collision`: the projectile collision layer and target mask.

Each `ShotDescriptor` carries bullet attributes, a spawn offset, a direction,
and `spawn_delay_sec`. The manager resolves the final spawn position from the
source's current center plus the offset when the shot fires.

A collision profile is complete when its layer and target mask are both set or
both `None`. A profile with no targets creates a projectile without entity
collision.

## Typical Workflow

1. Ask the weapon or ability to produce its shot descriptions.
2. Set the firing `GameObject` as the request source.
3. Set both sides of the collision profile when entity hits are enabled.
4. Move the request into `request_fire`.
5. Let the scene-integrated manager process delayed shots.

Gameplay sends requests through the service. `RoomScene` owns the manager's
scene binding and update calls.

## Ownership and Lifetime

`ProjectileService` owns no runtime state. `ProjectileManager` owns the queued
shot records and keeps non-owning pointers to their source. The active scene
owns each spawned projectile through `std::unique_ptr`.

The source must remain alive until every delayed shot that uses it has fired or
the queue has been cleared. Destroying the source while delayed shots remain
would leave those queued records without a valid spawn origin.

## Failure and Empty Results

`request_fire` returns `void` and reports rejected input through the logger. It
stops immediately when the source is null or already destroyed, or when the
shot list is empty.

The manager drops the request when no scene and physics runtime are bound. It
skips individual shots with a non-finite delay. An incomplete collision profile
is logged but the request still enters the queue.

## Example

```cpp
ProjectileFireRequest request;
request.source = this;
request.shots = _wand.attack(direction);
request.collision.layer =
    engine::physics::CollisionLayer::PlayerProjectile;
request.collision.targets =
    engine::physics::CollisionTarget::Enemy;

PROJECTILE_SERVICE->request_fire(std::move(request));
```
