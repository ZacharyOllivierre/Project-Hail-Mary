# 项目现状说明（中文）

## 项目目前在做什么

这个项目正在开发一个基于 SDL2 的 2D 俯视角战斗游戏原型。

从当前代码结构看，它的核心目标不是只做一个渲染 Demo，也不是只验证单个算法，而是在搭建一套可以持续扩展的游戏基础框架。当前已经具备程序启动、资源加载、场景切换、房间生成、玩家控制、敌人生成、投射物攻击、基础特效和部分 UI，因此它更像一个“可运行的战斗原型”或“垂直切片早期版本”。

目前的主流程比较明确：

1. 启动程序。
2. 初始化窗口、渲染器、音频、字体和输入系统。
3. 进入启动加载场景，显示预加载图片并加载资源。
4. 切换到主菜单。
5. 从主菜单进入战斗房间场景。
6. 在单个房间中进行移动、瞄准、攻击和战斗测试。

所以，这个项目当前最核心的事情，是把“游戏运行框架”和“房间战斗玩法”先搭起来。

## 项目目前已经有的内容

## 1. 程序主循环和应用框架

项目已经有完整的程序入口和主循环。

这部分负责：

1. 初始化 SDL2 及其相关模块。
2. 创建窗口和渲染器。
3. 轮询输入事件。
4. 驱动场景更新与渲染。
5. 驱动音频更新。
6. 接入 ImGui 调试层。

这说明项目已经不是“零散功能拼接”，而是具备了稳定的运行骨架。后续新增角色、地图、UI、战斗机制时，都可以挂接在这套主循环上。

## 2. 场景系统已经接通

项目已经实现了场景切换，并且当前有三类明确场景：

1. 启动加载场景。
2. 主菜单场景。
3. 房间战斗场景。

这意味着游戏流程已经具备最基础的结构，而不是所有逻辑都硬塞在一个文件里。以后如果要加入结算界面、暂停菜单、Boss 房间、过场剧情、选关界面，场景系统本身已经能承载这些内容。

## 3. 资源加载管线已经存在

项目已经有一套比较完整的资源启动流程，用配置文件统一加载：

1. 字体。
2. 音效。
3. 纹理。
4. 角色动画。
5. 特效动画。

这部分很重要，因为它说明项目已经开始从“代码写死资源路径”转向“配置驱动资源管理”。

它的价值在于：

1. 更方便替换资源。
2. 更方便多人协作。
3. 更容易扩展新角色、新动画和新特效。
4. 后续更适合做正式内容生产。

## 4. 房间地图和地块渲染已经可用

项目已经有房间地图对象，并能把 tile map 渲染成实际房间。

当前能看出它已经支持：

1. 地板。
2. 墙体。
3. 墙角。
4. 空白区域。
5. 图块贴图映射。

这说明地图不只是一个抽象数组，而是已经能转成可见场景。对于战斗游戏来说，这一步很关键，因为敌人生成、碰撞判定、投射物移动和玩家站位都依赖地图结构。

## 5. 玩家角色控制已经接通

当前玩家已经具备基础可玩能力：

1. 移动。
2. 朝向切换。
3. 动画状态切换。
4. 攻击输入响应。
5. 投射物发射请求。
6. 攻击特效触发。

这说明玩家不是“只能在屏幕上显示的静态角色”，而是已经接进输入、战斗、动画和效果系统，是当前玩法链条中的核心对象。

## 6. 敌人生成系统已经存在

项目已经能在房间内批量生成多种敌人，而且不是简单写死坐标。

当前生成逻辑会：

1. 读取房间 tile map。
2. 寻找可站立的地板区域。
3. 检查生成位置是否可用。
4. 按敌人类型创建不同敌人实例。

目前已接入的敌人类型包括：

1. Skeleton。
2. SkeletonElite。
3. Slime。
4. GoblinWitch。
5. Wizard。

这说明项目已经有了“战斗内容池”的基础，而不只是单一测试敌人。

## 7. 战斗系统已经有初步拆分

从目录结构看，项目已经把战斗拆成多个模块，而不是混在一个角色类里。

当前可见的战斗模块包括：

1. Bullet。
2. Projectile。
3. ProjectileManager。
4. ProjectileService。
5. Wand。
6. StatusEffect。
7. BulletBehavior。
8. 战斗网格和符文相关结构。

这说明项目在设计上已经朝“可扩展战斗系统”走，而不是一次性写死攻击逻辑。

## 8. 基础 UI 已经能工作

主菜单已经有基础界面和开始按钮，说明项目的 UI 交互链已经接上。

现在它至少已经验证了：

1. 文本显示。
2. 按钮渲染。
3. 鼠标点击响应。
4. 键盘确认输入。
5. UI 触发场景切换。

虽然还比较简单，但这已经足够支撑原型阶段的菜单和基本界面开发。

## 9. 有基础测试，但范围很有限

项目不是完全没有测试。

当前仓库里至少已经能看到：

1. logger 相关测试。
2. UI widget 相关测试代码。

这说明团队对稳定性和基础功能验证是有意识的，只是测试体系还远没有铺开。

## 10. 有一定的工程化意识

项目里已经包含：

1. CMake 构建结构。
2. application、engine、gameplay 分层。
3. docs 文档目录。
4. 代码规范文档。
5. thirdparty 依赖管理。

这说明它不是随意堆代码的课程作业雏形，而是已经有明显的工程组织意识。

## 项目目前缺乏的内容

## 1. 缺完整的游戏闭环

这是当前最明显的缺口。

现在虽然已经能进入战斗房间，但还没有看到完整的“开始一局 -> 战斗推进 -> 结算 -> 下一步”的闭环。

当前缺少的闭环内容包括：

1. 胜利判定后的推进。
2. 失败后的重开或返回流程。
3. 房间完成后的奖励或选择。
4. 下一房间或下一层的正式切换。
5. 通关或阶段结算流程。

换句话说，现在更像“能玩的战斗测试场”，还不是“完整的一局游戏”。

## 2. 缺地牢推进和关卡结构整合

代码中已经存在地牢图生成器，可以生成主路线房间和支路房间，还区分起点、遭遇、商店、礼物、Boss 等类型。

但目前这套系统没有真正接入运行流程。

这意味着现在缺的不是“想法”，而是“把想法接入真实玩法”。

当前还没形成这些内容：

1. 房间之间的正式跳转。
2. 玩家路径选择。
3. 多层关卡推进。
4. Boss 层或小 Boss 层的完整流程。
5. 地图生成结果与实际场景加载的联动。

## 3. 缺更完整的 UI 系统和界面内容

当前菜单能用，但非常基础。

从产品角度看，至少还缺：

1. 设置界面。
2. 退出按钮。
3. 暂停菜单。
4. 结算界面。
5. 死亡界面。
6. 更完整的 HUD。
7. 可能的背包、技能、升级或选择界面。

也就是说，现在 UI 更偏“验证功能”，还不是“支撑完整玩家体验”的界面系统。

## 4. 缺内容量

虽然项目已经有角色动画、敌人、贴图、音效和特效，但整体内容量仍然偏少。

目前的不足大概率包括：

1. 地图主题数量有限。
2. 房间种类有限。
3. 敌人种类虽然有多个，但整体规模还不大。
4. 武器、法杖、技能、符文或成长内容还不够丰富。
5. 音频资源量较少。
6. 背景音乐配置目前是空的。

这说明项目已经有“系统”，但还缺足够多的“内容”去支撑长时间游玩。

## 5. 缺战斗系统的打磨和收尾

项目中已经存在多条和战斗相关的 TODO，主要集中在这些方面：

1. 子弹碰撞盒与旋转贴图不完全对齐。
2. 符文槽位相关逻辑还不稳定。
3. 状态效果系统还需要重做或补全。
4. 某些效果交互还没有真正接入实体生命系统。
5. 部分战斗代码作者自己也标注了需要重构。

这类问题说明项目并不是没有设计，而是已经进入“功能初步有了，但机制还要精修”的阶段。

## 6. 缺正式文档说明

当前 README 几乎没有实际内容。

这会直接带来几个问题：

1. 新成员不知道项目目标是什么。
2. 外部读者不知道项目目前做到哪一步。
3. 别人不知道怎么构建和运行。
4. 不清楚依赖项和平台要求。
5. 不清楚玩法方向和后续计划。

这类缺口不会直接影响程序运行，但会明显影响协作效率。

## 7. 缺更完整的测试覆盖

虽然仓库里已经有测试代码，但从当前构建配置看，测试覆盖仍然比较薄。

当前明显还缺：

1. 房间生成测试。
2. 敌人生成测试。
3. 资源加载测试。
4. 战斗逻辑测试。
5. 场景切换测试。
6. 输入映射测试。
7. 集成级别测试。

而且已有的 UI 测试代码也没有完全接入测试目标，这说明测试体系还没有真正形成稳定流程。

## 8. 缺剧情、任务和世界观落地

仓库里已经有叙事方向文档，但从代码和资源配置看，还没有看到这些内容被大量实现进实际游戏中。

这意味着当前缺少的可能包括：

1. 角色设定落地。
2. 世界观文本。
3. 对话系统。
4. 任务目标。
5. 事件触发。
6. 剧情推进。

所以目前项目更偏玩法原型，而不是叙事完整的正式作品。

## 9. 缺存档、进度和长期系统

虽然路径管理器已经预留了 player_data、saves、logs 等运行目录，但从当前主流程看，还没有形成清晰的长期进度系统。

通常这类内容还需要补：

1. 存档读写。
2. 玩家局外成长。
3. 游戏设置保存。
4. 进度恢复。
5. 历史记录或统计。

这部分往往决定项目能否从“原型”走向“正式可持续游玩”。

## 当前阶段判断

如果用比较简洁的话来描述，这个项目现在处于：

“底层框架已经搭起来，单房间战斗已经能跑，但完整玩法循环和内容规模还没补齐。”

它现在最成熟的部分是：

1. 程序骨架。
2. 场景切换。
3. 资源加载。
4. 房间地图。
5. 玩家基础控制。
6. 敌人生成。
7. 投射物与基础战斗链路。

它现在最缺的部分是：

1. 完整游戏循环。
2. 地牢推进接入。
3. 更丰富的玩法内容。
4. 更完整的 UI。
5. 更扎实的测试。
6. 更明确的文档。
7. 叙事和长期系统落地。

## 一句话总结

这是一个已经脱离“空项目”阶段、并且具备明确玩法方向的 SDL2 游戏原型。

它已经有足够多的系统证明项目方向是成立的，但还缺把这些系统真正串成完整游戏体验的那一步。
